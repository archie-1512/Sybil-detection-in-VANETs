# Privacy-Preserving Sybil Detection in VANETs

Project for BCSE314L (Privacy and Security in IoT), VIT Vellore.

Vehicular Ad-hoc Networks (VANETs) let cars broadcast location, speed and
traffic info to each other over V2V communication. A Sybil attack is when
one malicious vehicle creates several fake identities and floods the
network with them to manipulate traffic decisions or hide its real
behaviour. Most detection methods deal with this by using the vehicle's
raw location/speed data directly, which isn't great for privacy since it
lets you track a driver over time. This project tries to detect Sybil
identities from pairwise mobility features instead, and adds Laplace noise
to the broadcast data before it's used, so detection doesn't need to see
a vehicle's exact position/speed.

## How it works

1. A SUMO traffic simulation generates realistic vehicle movement on a
   small grid road network.
2. For a subset of vehicles ("attackers"), the script fabricates 1-2 fake
   "ghost" identities per timestep that mimic the real vehicle's
   position/speed with some jitter — this is what an actual Sybil attack
   looks like (one physical vehicle, multiple broadcast identities).
3. At each timestep a receiving vehicle builds a neighbour list from
   whatever is in communication range, and pairs of neighbours get
   compared using 7 features: Euclidean distance to receiver, average
   speed, traffic flow, and DTW (Dynamic Time Warping) distance between
   their speed histories.
4. Before any of this is used, Laplace noise is added to the broadcast
   position/speed (differential privacy), so the pipeline never sees
   ground-truth data.
5. These labeled pairs (Sybil / Normal) get used to train a classifier.

Originally this used a CNN on the 7 features, but that's overkill for a
7-value tabular input with no spatial structure — a tree-based classifier
makes more sense here and is what's implemented now (Gradient Boosting,
compared against Random Forest and Logistic Regression).

## Repo structure

```
generate_dataset.py     # runs the SUMO/TraCI simulation, builds the labeled dataset
laplace_noise.py         # differential privacy module (adds noise to broadcast data)
train_model.py           # trains + compares Logistic Regression / Random Forest / Gradient Boosting
predict_demo.py          # quick scenario tests against the trained model
network/                 # SUMO network + traffic demand + config
sumo_features_dataset.csv   # generated dataset (~15.5k pairs)
sybil_model.pkl           # trained model (Gradient Boosting)
```

## Setup

```bash
pip install -r requirements.txt
```

SUMO comes from the `eclipse-sumo` pip package (headless, no separate
install needed).

## Running it

```bash
# build the road network + traffic demand (only needed once, or to change scenario)
bash network/build_network.sh

# run the simulation and generate the labeled dataset
python3 generate_dataset.py --steps 600 --out sumo_features_dataset.csv

# train the models
python3 train_model.py --csv sumo_features_dataset.csv --out sybil_model.pkl

# sanity check on a few hand-picked scenarios
python3 predict_demo.py
```

`generate_dataset.py --no-noise` skips the Laplace noise step if you want
to compare detection performance with vs without privacy protection.

## Results

Dataset: 15,496 pairs (11,657 Normal / 3,839 Sybil, ~24.8% Sybil)

Best model — Gradient Boosting:
- Accuracy: 88.9%
- Precision: 0.79
- Recall: 0.75
- F1: 0.77

DTW distance between speed histories ends up being by far the most
important feature (~68%), which makes sense — a fake identity's speed
trace is basically an echo of its real parent vehicle's trace, so the two
end up moving almost identically.

Without the Laplace noise, accuracy goes up to ~91.3% — so the privacy
mechanism costs about 2-3 points of accuracy. That trade-off is the whole
point of the project rather than something to hide.

## Limitations

- Sybil ground truth is synthetic (ghost identities generated by jittering
  a real vehicle's trajectory) since there's no real-world labeled VANET
  Sybil dataset to train on.
- Low-speed/congested traffic pairs are under-represented in the training
  data because the SUMO traffic demand is randomly generated and mostly
  free-flowing, so the classifier is less reliable in heavy congestion.
- Simulation is on a small 2x2 grid network — hasn't been tested on
  larger/more realistic road topologies.
